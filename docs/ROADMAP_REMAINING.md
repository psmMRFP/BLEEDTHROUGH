# 后续开发路线与验收计划

更新：2026-09-23。初始规划基线：`origin/main` 的 `2ef4017`；PR #13（知识状态）和 #14（专服遥测）均已合并。本文件逐项标注当前实施与验收状态；不修改原始 DOCX。

## 使用方式与状态

- `[ ]`：尚未完成；可能尚未实现，也可能缺少技术验证，后文必须说明。
- `[~]`：实现已有，明确列出的验证仍待执行；不得直接理解为可发布。
- `[x]`：该条所写范围已完成且有证据；不自动代表其所属 Phase 全部完成。
- 每项分别记录实现、自动测试、客户端／专服、真实多人、正式资产与体验状态。真人测试暂缺时保留待验收，不阻止无依赖的技术工作。
- 下文任务编号与先后顺序是工程拆分建议；新增玩法参数、世界生成高度、终局条件和外部版本仍须在对应阶段开始前形成决策记录。不给整个项目虚构日历工期。
- 开始每个子阶段前，重新阅读 AGENTS.md，并只读取与当前子阶段及其直接前置／接口相关的设计、原始 DOCX、实施计划和本路线章节；检查工作区、远端 main 和 PR。小范围实现、验证、更新记录、提交分支／Draft PR，由用户合并。

设计来源：DOCX 第七、十六、十七、十九、二十三、二十五、二十七节，以及 [设计文档目录](README.md)。原始文档早期“维度隔离结构”的叙述，由第十六节对 Ancient Anchors 的局部观测／稳定设施定位具体限定；不据此新增宇宙防火墙。玩家保留、清除或融合的自由选择沿用既定设计。

## Phase 7 收尾：近期可执行任务

### 7.6-R 研究反馈与生命周期

- [ ] 保留已有观察 ID；把研究条件接入最小 Advancement／数据驱动研究记录，提供中英文本。先做观察与结果可见，不新增完整 Quest UI。玩家先做工业、后发现 Rift 也应得到正确结果，两条研究可同时成立。
- [ ] 明确研究条件与玩法权限的关系：早期观察不会永久锁定路线，不借任务门阻止自然入口；避免重复登录反复发奖励或提示。
- [ ] 补齐事件级验证：Capability 注册与挂载、死亡 Clone、End 返回复制、真实 player NBT 保存／加载、无历史版本、未知观察值与数据包重载。分清真实服务端对象测试和真实网络玩家测试。
- [ ] 验证 Rift 交互的取消／DENY 语义；烧灼与工业仅成功时记观察；极寒重复查询不持续产生无用工作。修复须以具体复现为依据。
- [ ] 验收：乱序和重复操作测试、两份玩家状态隔离、研究可见结果、旧存档无知识初始化、资源加载与普通专服保存通过；真实玩家反馈与双客户端重连留 `[~]`。

建议独立 PR；主要涉及 `progression/`、Advancement／语言资源和针对性测试。不得把已有的纯数据 `copyFrom` 测试写成死亡事件已通过。

### 7.7-A 遥测可用于验收

- [ ] 以有界窗口累计 tick 时间、正向／回退总处理量峰值、预算违规次数和每 Rift 处理量；记录实际配置预算。每 Rift 统计需限制容量并清除失效源。
- [ ] 记录会话 ID、构建提交、启动时间、采样窗口时长、GC 次数／耗时及已加载区块／实体数量。使用有界聚合；若报告 p95/p99，应说明采样与计算方法。
- [ ] 存档大小统计移出服务端 tick 的全目录同步扫描；后台只处理文件路径，禁止持有世界／区块对象，停止时回收任务。区分游戏存档与遥测自身增长。
- [ ] 验证启用／关闭／重新启用、表头、重启追加、写失败和日志轮转；磁盘错误不应杀死服务器，错误采样标为缺失而非假定零。
- [ ] 验收：窗口峰值与超预算检测测试、故障测试、遥测开关对照、普通专服多条采样与正常保存关闭；这一步仍不代表长测完成。

### 7.7-B 无人专服真实长测

- [ ] 建立独立持久测试目录与固定 seed、配置、坐标和版本清单；禁止复用 GameTest 默认世界作为长期证据。
- [ ] 编写可复跑控制脚本：启动等待 Done、执行固定命令、记录时间／退出码、正常 stop、重启检查。保留完整会话 ID，不能凭一个 shell 返回或首条 CSV 断言正常退出。
- [ ] 测试夹具在限定区域保持区块加载，放置活跃／休眠 Rift、受保护结构、待恢复组织、已喂养的受伤膜墙；可放置有限已存在生态实体验证 AI。forceload 仅用于夹具，产品演化仍不得自行加载区块。
- [ ] 先跑短演练验证所有操作可达，再进行至少 3 小时累计真实在线运行；记录重启分段，另保留一次足够长的不中断稳定负载段。覆盖暂停／恢复、reload、保存／重启、卸载／加载、有限 rollback 与恢复后玩家覆盖保护。
- [ ] Heart Pump 当前为交互加工，单纯放置不产生加工负载。自动化可使用有明确身份的服务端交互夹具，但需记录其覆盖边界；无人场景不能声称覆盖依赖真实玩家的自然生成和网络同步。
- [ ] 验收：无崩溃和存档丢失；预算违规为零；固定负载下队列可解释且有界；以预热后 GC 低水位／趋势判断内存，以稳定区和新生成区分别解释存档增长。MSPT 与同机器无负载／遥测关闭对照比较，先冻结负载与目标再跑，不事后挑阈值。

### 7.7-C 真人与发布验收

- [ ] 真实玩家触发生态生成、工业交互、下界往返、死亡／重连、多人知识隔离和客户端表现；至少双客户端覆盖同步差异。
- [ ] 汇总 7.1–7.7 的技术证据、正式资产缺口、体验项、已知缺陷和复现方法，形成 Core Alpha 验收报告。
- [ ] 无真人时可以完成 A／B；C 保留待测。无长测时可以准备 Phase 8 设计与测试夹具，但不得把 Phase 7 或发布门标为通过。
